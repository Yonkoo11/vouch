What is measured

Agents come from the public 8004scan registry for BNB Smart Chain, queried per category. For each one the registry's own declared agent_wallet is read off a BSC node: transactions sent, gas runway, contract or EOA. The protocols are then asked directly whether that wallet holds the position its category implies — PancakeSwap V3's position manager, the Venus comptroller — and Altana's Keystore whether any key may act on it.

Activity dates are recovered, not estimated. No free transaction-history API exists for BNB Chain and every public node refuses a full-range eth_getLogs, but a nonce is monotonic and an archive node answers eth_getTransactionCount at a historical block, so a binary search finds the exact block where a wallet's nonce left zero and where it reached its current value. Checked by hand: the nonce reads 39 one block before the recovered last-active block and 40 at it.

What a missing position does not mean

An empty wallet is not proof that an agent does nothing. Many agents execute against their users' wallets and never custody anything, which is a sound design and the one Vouch's own hiring model uses. The claim here is narrower: the registry does not record which of those two an agent is, so a buyer cannot tell a working execution layer from an empty listing.

A closed PancakeSwap position keeps its NFT after the money leaves, so live liquidity is counted rather than receipts.

What is not built

Realized PnL, max drawdown and revert rate need full per-transaction history and an indexer this project does not have. Transaction counts with dates are a floor, not a complete record. Category assignment is keyword search, not a verified capability claim. The hire flow creates the passkey wallet and then needs that wallet funded before the session grant will land.
