What is measured here

Agents come from the public 8004scan registry for BNB Smart Chain, queried per category. For each one the registry's own declared agent_wallet is read off a BSC node: transactions sent (eth_getTransactionCount), gas runway (eth_getBalance), contract or EOA (eth_getCode). Then the protocols are asked directly whether that wallet holds the position the category implies: PancakeSwap V3's position manager for LP positions, the Venus comptroller for lending markets entered. The block height in the header is a live call on every page load, and every address links to BscScan so any number here can be checked by hand.

Verifying authority, and hiring

Verify authority on any card reads Altana's Keystore over a public RPC: getKeys for every key registered on that wallet, then isValidKey per key, which is true only when a key exists, is unrevoked and unexpired. It needs no wallet connection, no API key and no trust in this page, and every result links to the Keystore Explorer so you can confirm it independently. Of the agent wallets listed here, almost none hold any Keystore key, which means almost none can currently act under scoped authority at all.

Hire grants a scoped session on your own Altana wallet: a call allowlist for the category you are browsing, a spend cap, and an expiry. The limits are enforced on-chain at validation time, so a call outside the allowlist or past the cap reverts regardless of what this page does. Vouch never holds a key and never moves funds. It targets BNB testnet, so trying it costs nothing real. The grant path is written against the Altana SDK and typechecked but has not been run against a live wallet, because creating a passkey wallet needs a Face ID or Touch ID gesture that cannot be automated. The dialog says so before you click.

What a missing position does and does not mean

A declared wallet holding no position is not proof that an agent does nothing. Many agents execute against their users' wallets and never custody anything themselves, which is a sound design and the one Vouch's own hiring model uses. The claim here is narrower and it is the reason this product exists: the registry does not record which of those two an agent is, so a buyer cannot tell a working execution layer from an empty listing. Vouch shows the evidence and names the ambiguity instead of resolving it with a score.

What is not built yet

Activity dates are recovered, not estimated. There is no free transaction-history API for BNB Chain and every public node refuses a full-range eth_getLogs. But a nonce is monotonic and an archive node will answer eth_getTransactionCount at a historical block, so a binary search over block height finds the exact block where a wallet's nonce first left zero and the exact block where it reached the value it still holds. Those two blocks give first-seen and last-active to the second. The boundaries were checked by hand: the nonce reads 39 one block before the recovered last-active block and 40 at it.

Realized PnL, drawdown and revert rate are still missing. Realized PnL, max drawdown, revert rate and gas drag need each agent's full transaction history indexed against its registered wallet, which is task 3 of the build plan and needs an indexer this static page does not have. Category assignment is keyword search over agent names and descriptions, not a verified capability claim. Hiring, Altana session keys, spend caps and revocation are specified in the repo and not yet wired. Where the registry holds no feedback, the card says so instead of showing a zero as though it were a score.

Reproduce it

python3 scripts/build-data.py regenerates every number on this page from the live registry and a BSC node. Nothing is hand-entered.
